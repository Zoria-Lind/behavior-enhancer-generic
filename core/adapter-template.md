# 通用适配器模板(ADAPTIVE 模式)

> 给 Agent 的填空模板,配合 SKILL.md §8 使用。**语义函数从现成 semantics 文件抄,不许改**;
> 只填传输层。三个挂点按宿主能力填一个算一个;没有的挂点 = 对应 feature 最多 SOFT。

## 挂点 1:工具调用前(pre / veto 通道)

宿主如何注册"工具执行前回调,可返回否决"——查宿主文档/源码,写最小探针实测一次。

```
- F6 硬闸:命令匹配 FORBIDDEN 模式表 → 否决(带逃生计数 maxStrikes=3,同原因超 3 次放行)
- F3b 并发窗口:in-flight 计数 ≥ 档位 → 否决(档位状态来自语义;被否决的调用不计数)
- F1 读前检查:目标文件是重要文件(模式表 ∪ 行首注释形态 /force-read 标记)且覆盖有洞
  → 否决(文案给第一个未读区间 offset 指引)
- F5 写前快照:内容/磁盘均可,宿主能做什么用什么(新文件也登记:回滚=删除)
```

## 挂点 2:工具调用后(post / 观察通道)

```
- F1:read 成功 → 记覆盖区间(offset+limit 算下界,区间并集,TTL 1h)
- F5:写后校验 lightParse → 坏则回滚 + 报告(报告要诚实说明回滚结果)
- F3a/F4:失败签名检测(isError + 退出码 + stderr 签名)→ 连续失败计数 → 达阈值注入停手提醒
- F3b:成功连击 → 档位阶梯恢复(1 → 连3成功 → 3 → 再3成功 → 不限)
```

## 挂点 3:提示注入(常驻 / 每轮通道)

```
- 纪律段(含实时档位行)——从现成适配器抄文本,把工具名换成宿主自己的;
- 若宿主只有常驻文件通道(AGENTS.md 类),写入片段即 SOFT 通道,同样有效。
```

## 状态

- 会话级:读覆盖注册表、in-flight、档位、连击;
- 跨会话(可选):统计计数;
- 存取方式按宿主能力:进程内内存 / 文件(原子写或锁)/ 宿主状态 API。**全部 fail-open**。

## 宿主陷阱自检(生成后逐条核对,静默失败 = 假 FULL)

1. 钩子注册是否受宿主静态校验器约束?(CC:hook 必须顶层声明、`$` 只能按 `$.noun.event` 拼写、
   无 matcher 的 tool.call 只能注册一个、`next` 是保留名)
2. 否决的输出协议?(字段名 / 退出码 / 静默约定——Codex 式:exit 2 + stderr = 拦截)
3. 放行的输出协议?(Codex 式:必须空 stdout;输出 allow 反而报错)
4. 状态读写在钩子内异常时是否 fail-open?绝不阻断工具执行。
5. 回滚在新文件/无删除 API 时怎么诚实处理?(CC 式:只能清空为空白文件,报告如实说)
6. 进程模型?(子进程 hook 有跨进程竞态:计数与登记必须同锁;进程内 hook 无此问题)
